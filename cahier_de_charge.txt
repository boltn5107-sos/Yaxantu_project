CAHIER DES CHARGES
PLATEFORME MARKETPLACE YAXANTU
Version 1.0

1. IDENTITÉ DU PROJET

Nom : Yaxantu

Type : Marketplace multi-vendeurs

Première version : Progressive Web App (PWA)

Stack principale :

* Frontend : Next.js + TypeScript
* Backend : Laravel
* Base de données : PostgreSQL
* Cache et files d'attente : Redis
* Stockage médias : stockage objet compatible S3
* Déploiement : Docker + CI/CD

Objectif général :

Créer une marketplace moderne permettant à toute personne d'acheter ou de vendre facilement, y compris les commerçants ayant une faible maîtrise du numérique ou de la lecture.

Yaxantu doit être simple sans être simpliste, moderne sans être générique et accessible sans donner l'impression d'être une application destinée uniquement aux utilisateurs débutants.

2. VISION

Yaxantu doit réduire la complexité du commerce en ligne.

L'utilisateur doit pouvoir :

* rechercher un produit par texte, voix ou image ;
* comprendre rapidement une fiche produit ;
* écouter les informations importantes ;
* acheter avec un parcours court ;
* suivre sa commande ;
* vendre un produit avec très peu de saisie ;
* communiquer avec les acheteurs ;
* recevoir et gérer ses paiements ;
* développer progressivement son activité.

L'intelligence artificielle sera prévue dès la conception, mais le fonctionnement essentiel de Yaxantu ne doit jamais dépendre de l'IA.

Si un service IA est indisponible, les fonctions commerciales principales doivent continuer à fonctionner.

3. POSITIONNEMENT UX

Yaxantu doit combiner :

* simplicité d'utilisation inspirée des applications grand public ;
* rapidité des services financiers numériques ;
* puissance fonctionnelle d'une grande marketplace ;
* accessibilité pour les utilisateurs ayant une faible littératie numérique ;
* architecture technique capable de supporter une croissance importante.

Yaxantu ne doit pas copier WhatsApp, Wave, Shopify, Alibaba, Amazon ou une autre plateforme.

Les bonnes pratiques peuvent être reprises, mais l'expérience utilisateur doit être conçue spécifiquement pour Yaxantu.

4. PRINCIPES DE DESIGN

Le design doit être :

* professionnel ;
* moderne ;
* sobre ;
* original ;
* lisible ;
* rapide ;
* cohérent ;
* mobile-first.

Éviter :

* les interfaces génériques ;
* les gradients excessifs ;
* les animations inutiles ;
* les énormes boutons ;
* les interfaces surchargées ;
* les emojis décoratifs ;
* les composants visuellement incohérents.

Les boutons doivent avoir une taille standard confortable.

Chaque composant doit appartenir à un design system cohérent.

5. ACCESSIBILITÉ

Yaxantu doit pouvoir être utilisé par :

* utilisateurs expérimentés ;
* utilisateurs débutants ;
* personnes lisant peu ;
* personnes ayant des difficultés avec les formulaires ;
* utilisateurs disposant d'un smartphone d'entrée de gamme.

L'interface ne doit cependant pas supposer qu'un utilisateur analphabète est incapable d'utiliser une interface moderne.

L'objectif est de proposer plusieurs modes d'interaction :

* visuel ;
* tactile ;
* vocal ;
* photographique ;
* textuel.

6. RÈGLE DE CODAGE VISUEL

Pour les actions importantes, utiliser une combinaison :

COULEUR + FORME + ICÔNE + POSITION + VOIX SI NÉCESSAIRE

La couleur ne doit jamais être le seul moyen de transmettre une information.

Exemples :

ACHETER

* couleur dédiée ;
* icône panier ;
* emplacement constant ;
* libellé court ;
* confirmation visuelle.

RETOUR

* icône flèche ;
* emplacement constant ;
* couleur secondaire.

SUCCÈS

* couleur de succès ;
* symbole de confirmation ;
* message clair.

ERREUR

* couleur d'erreur ;
* symbole explicite ;
* explication courte.

7. PALETTE

Fond principal :

* blanc ou gris très clair.

Couleur principale :

* bleu ou vert foncé.

Couleur d'accent :

* orange ou jaune vif réservé aux actions importantes.

Couleurs fonctionnelles :

* vert : succès ;
* rouge : erreur ;
* jaune : attention.

La palette doit rester limitée et cohérente.

8. PAGE D'ACCUEIL

La page d'accueil doit présenter immédiatement :

* recherche ;
* recherche vocale ;
* recherche par image ;
* catégories principales ;
* produits populaires ;
* produits proches ;
* vendeurs vérifiés ;
* offres ;
* recommandations.

La recherche doit être l'élément central de l'expérience.

9. CATÉGORIES

L'interface principale ne doit pas afficher une multitude de catégories.

Prévoir 3 à 4 catégories principales visibles directement.

Chaque catégorie doit être représentée par :

* image ;
* icône ;
* nom court.

Les catégories détaillées restent accessibles après sélection.

10. FICHE PRODUIT

Une fiche produit doit contenir :

* photo HD ;
* galerie d'images ;
* prix en chiffres ;
* disponibilité ;
* quantité ;
* vendeur ;
* statut de vérification ;
* localisation lorsque pertinente ;
* informations principales ;
* description ;
* avis ;
* avis audio ;
* informations de livraison ;
* bouton d'achat ;
* ajout au panier ;
* favoris.

La description doit pouvoir être lue à voix haute.

11. RECHERCHE

Trois modes principaux :

A. Recherche texte

Pour les utilisateurs qui préfèrent saisir une requête.

B. Recherche vocale

L'utilisateur parle naturellement.

Exemple :

"Je cherche un téléphone Samsung à moins de 150 000 francs."

Le système transforme la demande en critères de recherche.

C. Recherche par image

L'utilisateur photographie un produit.

Le système peut identifier :

* type de produit ;
* catégorie ;
* caractéristiques visibles ;
* produits similaires.

12. FILTRES

Les filtres doivent privilégier la sélection visuelle.

Exemples :

* couleurs ;
* tailles ;
* prix ;
* distance ;
* disponibilité ;
* état du produit ;
* vendeur vérifié.

Les sélections doivent être représentées clairement.

Éviter les interfaces composées de longues listes déroulantes.

13. PANIER

Le panier doit permettre :

* ajout ;
* suppression ;
* modification de quantité ;
* calcul du sous-total ;
* frais de livraison ;
* total ;
* vérification du stock.

Les prix doivent toujours être affichés clairement en chiffres.

14. PARCOURS D'ACHAT

Objectif :

1. Produit
2. Livraison
3. Paiement
4. Confirmation

* sélection tactile ;
* adresse enregistrée ;
* localisation ;
* reconnaissance vocale ;
* informations préremplies ;
* confirmation vocale.

Les actions financières sensibles doivent toujours recevoir une confirmation claire.

15. PAIEMENT

* rapprochement ;
* historique ;
* idempotence.

5. Publier

Exemple :

"J'ai 20 sacs à 8 000 francs."

Produit : sac
Quantité : 20
Prix : 8 000 FCFA

41. CRITÈRES DE RÉUSSITE

Yaxantu doit permettre :

* à un utilisateur de comprendre rapidement comment acheter ;
* à un commerçant de publier un produit simplement ;
* aux fonctions principales de fonctionner sans IA ;
* aux opérations financières d'être validées côté serveur ;
* aux données sensibles d'être protégées ;
* à la PWA de fonctionner correctement sur mobile ;
* aux parcours principaux de rester courts ;
* à l'interface d'être utilisable avec peu de lecture ;
* à l'architecture d'évoluer sans réécriture complète.

42. PRINCIPE DIRECTEUR

Yaxantu ne doit pas être simplement un site de vente.

Yaxantu doit devenir une infrastructure de commerce accessible.

ACHETER simplement.

VENDRE simplement.

COMPRENDRE rapidement.

FAIRE CONFIANCE.

ÉVOLUER sans reconstruire la plateforme.
